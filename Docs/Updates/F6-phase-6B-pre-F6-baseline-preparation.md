## 9. Safety and recovery

- Every write must use exact target literals and same-connection identity guard. Reject LocalDB, production, environment-derived connection strings, arbitrary servers, unexpected database/state/version/ledger and mismatched script hash. A transport failure must not trigger fallback connection selection.
- Recheck schema/ledger boundaries before seed/backup and F6 absence after each stage. No latest migration, EnsureCreated, migration-history editing or extra preferred-definition .sql application.
- DDL failure/interruption: stop immediately; preserve SQL error/batch/hash and inspect actual ledger/schema under separately authorized access. Earlier migration transactions may have committed. Do not retry the `0` script on a nonempty database. A reviewed remaining-range script may be approved only when committed migration boundaries and schema match exactly; otherwise approve a disposable recovery procedure separately. Drop/recreate, Down and schema patching are not automatic permissions.
- Seed failure: transaction rollback and no partial data expected. Lost acknowledgement requires independent complete manifest inspection. If partial data exists, stop and investigate; no deletion of rows to make counts pass. Reseed only after a clean approved state or accept a fully matching committed seed.
- Backup failure: no F6 rehearsal; correct permissions/storage and retry to a new approved file. Restore failure: preserve source/backup, stop and inspect only approved target/files; no WITH REPLACE or broad cleanup. Recovery of an existing damaged target needs separate authorization.
- Current F6 application cannot be assumed compatible with pre-F6 schema even flags false; do not launch it against baseline. Once this preparation succeeds, stop at recoverable pre-F6 state. Later F6 Up/enrollment/concurrency work needs a new authorization.
- SQL Server 2019 Express compatibility150 is useful local provider evidence, not proof of production equivalence. SmarterASP SQL engine/version/compatibility/collation/permissions/topology/load remain unverified. Record local patch/build and revisit production-equivalent rehearsal under P6/P7.
