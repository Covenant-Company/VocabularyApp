```sql
SELECT t.name AS TableName, c.name AS ColumnName, ty.name AS SqlType,
       c.max_length, c.is_nullable, c.precision, c.scale, dc.definition AS DefaultDefinition
FROM sys.tables t
JOIN sys.columns c ON c.object_id=t.object_id
JOIN sys.types ty ON ty.user_type_id=c.user_type_id
LEFT JOIN sys.default_constraints dc ON dc.object_id=c.default_object_id
WHERE t.name IN ('UserWordReviewStates','ReviewSessions','ReviewSessionItems','ReviewHistories')
   OR (t.name='WordDefinitions' AND c.name='ContentRevision')
ORDER BY t.name,c.column_id;
SELECT name, OBJECT_NAME(parent_object_id) AS TableName, definition, is_disabled, is_not_trusted
FROM sys.check_constraints
WHERE name LIKE 'CK_Review%' OR name LIKE 'CK_UserWordReviewStates%' OR name='CK_WordDefinitions_ContentRevision';
SELECT fk.name, OBJECT_NAME(fk.parent_object_id) AS ChildTable,
       OBJECT_NAME(fk.referenced_object_id) AS ParentTable, fk.delete_referential_action_desc,
       fk.is_disabled, fk.is_not_trusted
FROM sys.foreign_keys fk
WHERE OBJECT_NAME(fk.parent_object_id) IN ('UserWordReviewStates','ReviewSessions','ReviewSessionItems','ReviewHistories');
```

## 4. Enrollment and catch-up procedure

Use `scripts/database/Enroll-F6ReviewStates.sql` outside an enclosing transaction. Operators must verify schema readiness and keep reviews disabled. The script deliberately defaults EnrollmentAtUtc to NULL and throws until a captured, approved UTC instant is supplied. It never obtains a changing clock value per batch.

| Parameter | Required behavior |
|---|---|
| Mode | `initial` or `catch-up`; both execute the same insert-only operation. |
| EnrollmentAtUtc | Explicit datetime2(7) UTC rollout reference, recorded and reused for legacy initial/catch-up runs. SQL datetime2 does not carry a timezone; correct UTC input is the operator's responsibility. |
| BatchSize | Default 1000; allowed 1..10000, tune from measured locks/duration. |
| AfterUserWordId | Default 0; resume at last reported committed key only if that run was interrupted. Final catch-up starts at 0 to catch any missing lower IDs. |
| StopAtUserWordId | NULL captures MAX(Id) at run start; explicit upper bound is allowed. New inserts above it require later catch-up. |
| MaximumBatches | Default 100; allowed 1..10000, limits each invocation. Resume or rerun to finish larger inventories. |

Each keyset batch uses one transaction: select ascending saved IDs, resolve preferred/fallback meanings and insert missing states, then commit and report the last key/count. NOT EXISTS uses UPDLOCK/HOLDLOCK on the state PK to serialize competing inserts within a batch. Unknown constraint errors and deadlocks are rolled back/rethrown rather than hidden; previous committed batches survive. An operator retry resumes/reruns the idempotent operation. This is not a claim that SQL Server race behavior has already been tested.

Every saved word is enrolled, including blocked meanings. Preferred selection must belong to the saved word/POS. A valid explicit blank preferred meaning is blocked; otherwise usable fallback ordering is DisplayOrder then definition ID. Unicode-whitespace-only words/definitions are blocked using the explicit whitespace set and BIN2 comparison; dictionary text is not rewritten. Meaning ID/revision are paired null for blocked words. Enrollment fields are New=0, count/interval/lapse=0, LastReviewedAt=NULL, algorithm=interval-v1 and version=1, EnrollmentAt=NextReviewAt=the captured reference. No quiz field, note, favorite, preference, session, receipt or history is changed/created by enrollment.

Rerun initial enrollment and confirm **zero inserted existing states**, unchanged schedules and zero fabricated history/sessions. Insert legacy saved words concurrently before activation, rerun catch-up from 0 and verify the anti-join reaches zero after writes are paused/old writers retired. New application enrollment hooks do not exist in Phase 2; they must be implemented in Phase 3 before activation.

Insert-only catch-up deliberately does not reset already enrolled states when old preferred/content writers change them. The verification script lists meaning/revision mismatches; these are stop conditions requiring the controlled reconciliation/reset policy in later service/rollout work. Do not silently bulk-reset schedules to make verification pass. No phase-2 preferred-definition hook or live content editor exists.
